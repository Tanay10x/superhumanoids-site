# Render and simulation asset pipeline

Everything under `assets/frames/` and `assets/sim/` is generated by these scripts.
Paths inside them point at a local working folder (`/home/tanay/sh-build`); change `ROOT`/`OUT` to match yours.

## Inputs
- Robot models: open-source MJCF models placed under `ROOT/models/{humanoid,quadruped,arm}/` with their main files renamed `humanoid.xml`, `quadruped.xml` and `arm.xml`. See `THIRD_PARTY_NOTICES.md` for their licenses.
- Lighting and floor: a CC0 studio HDRI (`studio.exr`) and a CC0 concrete PBR texture set.
- Blender 4.2 LTS, with `mujoco` pip-installed into Blender's bundled Python.

## Scroll sequences (`assets/frames/<robot>/{d,m}`)
1. `motion.py`: kinematic motion per robot, driven by MuJoCo (humanoid reach, quadruped stepping gait, arm IK pick).
2. `render.py`: builds the scene from MuJoCo's own mesh buffers and renders it with Cycles.
   - Desktop: `blender -b -P render.py -- humanoid out/humanoid --frames 90 --samples 96 --res 1920x1080`
   - Phones: add `--portrait --res 720x1280` (every other frame, subject centred)
3. `encode.sh <robot>`: converts the PNGs to WebP.
4. `telemetry.py`: exports the joint angles shown in the hero readout.

Vendor markings are removed from every model: logo meshes and decals are dropped, and `erase_lettering.py` heals the lettering cut into the quadruped shell. Renders and the live sim both use the cleaned models.

## Live simulation (`assets/sim/`)
1. `decimate.py`: Blender decimation of the model collection meshes into a web copy.
2. `webpack.py`: writes a physics-only `.mjb` (`discardvisual`) and a compact visual mesh pack per robot, both gzipped. The page inflates them with `DecompressionStream`.
   Scene files: `quadruped_scene.xml`, `arm_scene.xml` (place them next to the model XML they include).
